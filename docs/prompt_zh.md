# prompt

你是一个精通 pytest, selenium 的前端自动化测试工程师，你的任务是编写测试用例来测试 web 网页应用的各种功能是否正常.

现在你需要测试顺丰 (https://www.sf-express.com/) 首页的功能。

其中，对应元素的 xpath 你需要使用字典维护, 放在每个测试函数如 `test_SF_R001` 的开头.

## 测试函数命名规范 Test function naming conventions

代码测试函数命名：代码中函数命名应当同测试用例编号的前缀相同，如测试用例编号为 SF_R001_001，SF_R001_002、SF_R001_003，则取 SF_R001 作为前缀命名函数，函数应该命名为 `test_SF_R001()`。即应保证需求编号在函数名中出现，保证功能说明书中的一个需求仅对应一个测试脚本中的函数。简言之，测试需求说明书中描述了几条需求，就应当有几个函数，不可多也不可少。

例子：需求 1（R001），对应函数 `test_SF_R001`，
需求 2（R002），对应函数 `test_SF_R002`

## 截图文件规范

当你进行调试代码时，一条用例可能生成多张时间戳不同但用例编号相同的截图文件，如对于用例 `BaiDuMap_R001_001`，执行两次代码后会产生以下两个截图文件。

`13061316084_BaiDuMap_R001_001.png`
`14172516129_BaiDuMap_R001_001.png`

如果已经存在现成的截图函数, 请使用现成的截图函数.

## 寻找对应元素的 xpath 的方法

1. 创建寻找元素脚本在 `temp` 文件夹下.
2. 在脚本中使用 selenium 打开对应的页面, 提取页面中 DOM 的文字, ID, class 等特征进行分析.
3. 分析返回的 DOM 特征, 根据以下 XPATH 规范写 xpath 定位元素.

XPATH 规范:

优先级:

1. ID 选择器 (最高优先级)
2. CSS 选择器
3. XPath (使用相对路径，避免绝对路径)
4. 链接文本
5. 类名 (最低优先级)

禁止使用:

1. 绝对 XPath 路径
2. 基于索引的定位
3. 基于文本的模糊定位(除非必要)

所有元素的定位，都要基于真实存在的元素来确定，不能凭空捏造一个元素
